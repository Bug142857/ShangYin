- **项目记忆同步（v2.21.2 起，用户要求"换电脑/换账号也不丢上下文"）**：每次更新本记忆文件后，必须把全文同步拷贝到仓库 `docs/AI_PROJECT_MEMORY.md`（头部注明"由 AI 助手维护，与本地项目记忆同步"）并随 commit push——这是给 AI 的硬规则，不是可选项
- **发版流程（2026-09-16 用户确认延续，同日补充"每次也要完善README和Releases页面"）**：每次 bump 版本后——① **同步更新 README.md 功能描述**（新功能/行为变化写进对应章节）；② git tag vX.Y.Z 随 main 一起 push；③ **创建 GitHub Release 前必须先查是否已存在**（见下方「发版分工（2026-09-20 用户确认）」——已存在就只核对资产、绝不上传第二份；确实不存在才创建：中文 release notes + 上传 APK 资产）。gh CLI 未安装，用凭据管理器 GCM token（CredRead `git:https://github.com`，gho_ 开头）直调 REST API：POST /repos/Bug142857/ShangYin/releases + PATCH body 补中文 notes + uploads.github.com 上传资产。⚠️ 硬教训：PS1 脚本无 BOM 时含中文会被按 GBK 解析报语法错（脚本必须全英文/字符串用 [char] 拼）；`git credential fill` 管道传 stdin 有 CRLF/协议校验问题不可用；**GitHub API 资产名不支持中文（自动剥离非 ASCII），APK 资产名用 LaoZhengFenXiang-X.Y.Z.apk**；GitHub token 有效无需问用户
- **发版分工（2026-09-20 用户确认：不要再重复创建 Release）**：本仓库存在**并行会话/自动化**——只要 tag 推到 origin，另一端通常会在 **1 分钟内**自动创建 Release 并上传 `LaoZhengFenXiang-X.Y.Z.apk`（连续 v2.23.8 / v2.23.9 / v2.23.10 三轮都是它先建，本会话 POST 一律吃 `422 already_exists`）。**因此本会话发版流程固定为**：① commit（只加自己改过的文件）→ ② `git push origin main` → ③ `git tag -a vX.Y.Z` + `git push origin vX.Y.Z` → ④ **先查询** `GET https://api.github.com/repos/Bug142857/ShangYin/releases/tags/vX.Y.Z`：**200 = 已经建好 → 下载资产、解 `classes*.dex`、按 UTF8 搜本版独有标记核对是否同一份代码，核对通过就收工**（**绝不再次 POST 创建、绝不 PATCH/删除/覆盖对方的 Release 与资产**）；**404 = 还没建 → 等 60~120 秒重查一次，仍 404 才自己创建 + 上传**（⚠️ 2026-09-21 补充：404 也可能是对方**正在创建/草稿**状态——实测连续查 5 次（约 3 分钟）都 404，自己一 POST 立刻吃 `already_exists`，几秒后列表里就出现已发布版本。所以 **404 时先 `GET /releases?per_page=8` 看列表里的 `draft`/`assets`，别急着 POST**；核对是否同一份代码优先用 **SHA256 直比本地构建产物**）。⑤ 其余照旧：APK 拷桌面（`[System.IO.File]::Copy`，`Copy-Item` 会被沙箱拒）、README 与新功能描述同步、记忆同步到 `docs/AI_PROJECT_MEMORY.md` 并单独 commit。**⚠️ 拿到 `already_exists` 不代表出错，直接走 ④ 的核对流程即可。**
