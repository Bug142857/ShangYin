- **发版流程（2026-09-16 用户确认延续，同日补充"每次也要完善README和Releases页面"）**：每次 bump 版本后——① **同步更新 README.md 功能描述**（新功能/行为变化写进对应章节）；② git tag vX.Y.Z 随 main 一起 push；③ 创建 GitHub Release（中文 release notes + 上传 APK 资产）。gh CLI 未安装，用凭据管理器 GCM token（CredRead `git:https://github.com`，gho_ 开头）直调 REST API：POST /repos/Bug142857/ShangYin/releases + PATCH body 补中文 notes + uploads.github.com 上传资产。⚠️ 硬教训：PS1 脚本无 BOM 时含中文会被按 GBK 解析报语法错（脚本必须全英文/字符串用 [char] 拼）；`git credential fill` 管道传 stdin 有 CRLF/协议校验问题不可用；**GitHub API 资产名不支持中文（自动剥离非 ASCII），APK 资产名用 LaoZhengFenXiang-X.Y.Z.apk**；GitHub token 有效无需问用户
- **哔咔 code=200 修复（v2.13.2 / versionCode 92，commit 82db7f6，2026-09-16 已 push+Release）**：用户报"初始化失败，重试后一直转圈"。**根因=哔咔 API 成功码是 200 不是 1**（curl 实测 auth/register 和 categories 均返回 `{"code":200,"message":"success"}`），BikaClient 原 `code != 1` 判断把成功当失败抛"接口错误(code=200)"；且 register 响应**无 data 字段**（只有 code/message）→ request() 改为 `code==1||code==200` 放行 + requireData 参数（register 传 false）。次要 bug=LaunchedEffect(Unit) 不随 initError=null 重启 → 重试按钮加 retryKey 变更 key。**用户困惑澄清：haka_comic 注册的账号就是哔咔账号**（haka 注册直接调哔咔 auth/register 同一账号体系，凭据通用）→ H2 顶栏加 Person 图标 + BikaLoginDialog 手动登录自己账号（AlertDialog，登录成功覆盖 bika_token）。哔咔注册接口当前开放（实测可注册），自动游客账号方案可行
- APK 输出: release 包直接从 app/build/outputs/apk/release/ 复制到桌面，文件名保持 build 产物原名 老郑分享-{versionName}.apk；每次改完都要 git push；**commit 后直接自动 push，禁止再用 AskUserQuestion 征询推送确认（2026-09-11 用户授权，2026-09-16 用户第三次强调"之后帮我自动推送"——旧规则"拦截时 AskUserQuestion 征询"已废止；安全策略若拦截 push，直接重试让用户在 IDE 权限弹窗放行即可）**；注意被拦截的组合命令（add+commit+push）会整体不执行，放行后需重新逐段执行；每次正式修改后必须 bump versionCode/versionName
- 构建 shell 是 PowerShell（不支持 && 与 bash heredoc），用 `;` 分隔命令、提交信息用 git commit -F 文件；JAVA_HOME=D:\Java\jdk-21.0.12.1+1
- 同一文件多处修改严禁并行 Edit（互相覆盖导致改动丢失，已踩坑多次）；material-icons-extended 已引入（Cloud/CloudUpload 等可用），core 集只有基础图标
- 图片缓存：Coil diskCache 150MB LRU 自动清理（cache/image_cache）+ OkHttp HTTP 缓存 20MB（cache/http），手动清理由设置页"清理缓存"按钮触发（直接删目录兜底）
- 长按下载图片：CoverImage 默认 `downloadable=false`（不挂手势）；仅独立卡片场景显式 `downloadable=true`，使用 detectTapGestures 避免手势冲突

- 清单条目计数：使用 WITH RECURSIVE CTE 递归统计所有层级后代清单的条目总数（影响主页根清单卡片、详情页子清单卡片、设置页分类管理）

- 遮罩隐藏时机修复（v2.11.7 / versionCode 87，commit b7e23ac，2026-09-15 已 push）：v2.11.6 隐藏不生效（用户实测"没变化"）——根因=**PlayerView 的 controller 布局延迟 inflate，AndroidView update 首次回调时 findViewById 全是 null，?. 安全调用静默吞掉**（exo_settings 隐藏同理从未生效过，只是齿轮可能本来就没显示所以没暴露）。正解：所有 controller 内 View 操作（exo_controls_background/exo_settings 强制 GONE、exo_progress 挂 OnScrubListener）移到 **setControllerVisibilityListener 回调里**——回调触发时 controller 必已创建；遮罩/齿轮每次显隐都强制 GONE（幂等兜底 media3 内部重置），scrub listener 用 barBound flag 首次成功后不再绑；update 回调只留 pv.player 赋值。⚠️ 通用教训：**对 View 系控件 findViewById 拿 nullable 返回值时，"绑一次"逻辑必须确认时机在 inflate 之后，否则静默失败；用 `?.let { bound=true; ... }` 成功才置 flag**
- 片源链接测试（v2.10.5 / versionCode 75，commit 83f9f67，2026-09-14 已 push）：VodSource 加 testStatus（null/ok/dead/proxy）+testMsg+testAt（kotlinx 默认值兼容旧 JSON）；VodClient.testSource 返回带结果的 VodSource（请求 `?ac=videolist&wd=a&pg=1`，HTTP200+JSON code=1→ok"可用·共N部"，HTTP错误/非JSON/code!=1→dead，异常按 message 关键词 timeout/connect/refused/unreachable→proxy"需外网·直连超时/被拒"，其余→dead）；VodSourceScreen：点卡片测单个、顶栏 NetworkCheck"测试全部"（Semaphore(6) 并发 + joinAll，实时上屏 applyResult synchronized 防并发丢更新，结束 persist 落盘+Toast 汇总）；卡片状态行三色（ok 绿 0xFF2E7D32 / dead error红 / proxy 橙 0xFFEF6C00），汇总行"可用 n·已失效 m·需外网 k"。注意：测试结果随 vod_sources_json 持久化
- 播放起播提速 + 分类表兜底（v2.11.2 / versionCode 82，commit dd06179，2026-09-15 已 push）：① 播放慢=ExoPlayer 默认 bufferForPlaybackMs 2500ms 攒缓冲才开播 → DefaultLoadControl.setBufferDurationsMs(30000,60000,**1200**,3000) 起播减半以上（min/max 保持流畅、rebuffer 3000 防频繁卡）；② 源资源库分类缺失根因：**很多源 `?ac=videolist` 不带 class 字段（苹果CMS 标准分类表在 `?ac=list` 接口）**→ VodClient.fetchCategories（ac=list，解析 VodResp.categories），SourceBrowseScreen 首次加载 scope.async 并行补拉合并 distinctBy type_id（type_pid=0 顶级排前），VodCategory 加 type_pid；③ Kotlin 教训：`kotlinx.coroutines.async` 不是顶层函数（scope 扩展），不能全限定调用，须 import async 后 scope.async{}
- 手动分组防覆盖修复（v2.10.8 / versionCode 78，commit 5116e47，2026-09-14 已 push）：bug=编辑源改"所属目录"保存后，点卡片测试（点卡片=测试）时 testSource 的自动归组把 region 强制重置（ok/dead→cn、proxy→proxy），手动修改被顶回表现为"保存不生效"。修复：VodSource 加 `regionManual`（默认 false 兼容旧 JSON）；编辑对话框点目录 chip → regionTouched=true → 保存写 regionManual=true；testSource 中 `region = if (src.regionManual) src.region else 自动`；编辑保存时清空旧测试结果（testStatus/testMsg=null, testAt=0，地址变了旧结果不可信）；手动分组源状态行加" · 手动分组"后缀。教训：自动化逻辑（测试归组）与手动设置冲突时必须加 manual 标记
